        # useInfiniteScroll
        Loads paginated data through an async callback, accumulates the returned items, and requests the next page when a sentinel approaches the viewport. The item type is inferred from the loader’s return type.

        ## Behavior
        The first batch loads on mount when enabled and hasMore are true. After each successful request, items are appended and the sentinel is observed again so short lists continue filling the scroll container. The caller manages pagination and passes `hasMore: false` when there are no more results.

        Repeated load triggers are ignored while the current request is running. Failed requests preserve the loaded items and pause automatic loading until `retry()` or `reset()`. Reset, dataset changes, and unmount invalidate pending results. The hook does not cancel the client’s network request or prevent state updates inside the loader; cancellation and external state belong to the caller.

        ## Signature
        `useInfiniteScroll<T>(loader, options)`

        ## Code Examples
        Define the loader in your component so it can use your page state and request parameters. Return only the new items; the hook accumulates them. `Promise<Product[]>` infers `items` as `Product[]`, or specify `useInfiniteScroll<Product>` explicitly.
        </Unstyled>

        <RenderSource language={"tsx"}>
        ```
        import { useState } from 'react';
        import { useInfiniteScroll } from '@apple-pie/slice';

        type Product = { id: string; name: string };

        function Products() {
            const [page, setPage] = useState(1);
            const [hasMore, setHasMore] = useState(true);
            const [root, setRoot] = useState<HTMLDivElement | null>(null);

            const loadProducts = async (): Promise<Product[]> => {
                const response = await fetch(`/api/products?page=${page}`);
                if (!response.ok) throw new Error('Could not load products');
                const result: { products: Product[]; hasMore: boolean } = await response.json();
                setPage(current => current + 1);
                setHasMore(result.hasMore);
                return result.products;
            };

            const { items, sentinelRef, isLoading, error, retry, reset } =
                useInfiniteScroll<Product>(loadProducts, { root, hasMore });

            const startAgain = () => {
                setPage(1);
                setHasMore(true);
                reset();
                root?.scrollTo({ top: 0 });
            };

            return (
                <div>
                    <button type="button" disabled={isLoading} onClick={startAgain}>
                        Start again
                    </button>
                    <div ref={setRoot} style={{ overflowY: 'auto', height: 320 }}>
                        {items.map(product => <p key={product.id}>{product.name}</p>)}
                        <div ref={sentinelRef} style={{ height: 1 }} />
                        {isLoading && <p role="status">Loading…</p>}
                        {error && <button type="button" onClick={() => retry()}>Retry</button>}
                        {!hasMore && <p>You’ve reached the end.</p>}
                    </div>
                </div>
            );
        }
        ```

        ## Notes
        - The loader receives no arguments. It owns request parameters, pagination state, and any network cancellation.
        - Changing the loader alone does not reset the list. Subsequent requests use the latest committed loader, so it can read the updated page state without useCallback.
        - Change `resetKey` when the dataset changes. Update your external page state, hasMore, and filters together. If an old loader is still running, cancel it or guard its external state updates yourself.
        - `reset()` only resets the hook’s state. Reset caller-owned pagination in the same event, as shown above. A reset may start a new request while an invalidated request is still running.
        - Items are appended without deduplication. Empty results do not automatically stop loading; the caller must update hasMore.
        - Without IntersectionObserver, the first request and manual `loadMore()` still work. A Load more button can provide a keyboard-accessible alternative to scrolling.
        - TypeScript types describe the expected response; they do not validate server JSON. This hook does not virtualize rendered rows.
