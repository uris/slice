# TextField

Capture a short answer, search query, or password with an associated label and optional actions.

## Usage

```
import { TextField } from '@apple-pie/slice';

<TextField name="query" label="Search" placeholder="Search projects" onChange={myHandler} />
```

### Control text

```
<TextField label="Search" value={query} onChange={setQuery} />
```

### Add an action

```
<TextField label="Search" actionButton actionLabel="Search" onChange={setQuery} onAction={myHandler} />
```

## Behavior

With `behavior="appear"`, typing moves the label above the value; clearing returns it to the placeholder position. Focus alone does not move it, and the field keeps the same height.

With `onSubmit`, Enter submits once and blurs the input. Without it, the surrounding form handles submission. `onKeyDown` can cancel submission; Enter used to confirm composed text does not submit.

Native form reset restores `defaultValue` in uncontrolled fields. For controlled fields, reset the application's `value` state.

## Accessibility

The native input is associated with its visible `label`. Use `inputName` for a more specific accessible name; without a label, it falls back to `name` and then `Text input`. ARIA attributes are managed internally.

Disabled state covers the input and every auxiliary action. `readOnly` keeps the input focusable for copying while blocking edits, clearing, and the action button; password visibility can still be changed.

Icons are decorative. The clear control is not focusable while hidden or empty. The password action switches between `Show password` and `Hide password`. Error state marks the input invalid.

Reduced-motion preferences use the persistent stacked layout even when `behavior="appear"` is requested: the label stays above the value and the original placeholder remains below when empty. Color transitions and action fading also stop, including live changes; keyboard focus is retained.

## Motion

`transition` is merged with Slice’s Water transition for the optional action fade. Focus-color transitions use Water CSS timing. Reduced motion disables both and takes priority over custom timing.

## Events

- `onAction`: `() => void`. Runs when the nonempty, editable field’s action button is activated. Keep text in application state through `onChange` when the action needs it.
- `onBlur`: `(value: string) => void`. Reports the input’s current value once when it loses focus, including the blur after Enter submission.
- `onChange`: `(value: string) => void`. Reports edits and clear requests. Controlled fields keep displaying their current `value` until it is updated. Initialization, prop updates, and form reset do not emit this callback.
- `onClear`: `() => void`. Runs once after a valid clear request and the empty-string `onChange` callback.
- `onFocus`: `(value: string) => void`. Reports the current value on native input focus.
- `onKeyDown`: `(event: React.KeyboardEvent<HTMLInputElement>) => void`. Runs before built-in keyboard handling. Call `preventDefault` to cancel Enter submission and blur.
- `onPaste`: `(event: React.ClipboardEvent<HTMLInputElement>) => void`. Receives paste events while editing is allowed. Call `preventDefault` to replace native paste behavior.
- `onSubmit`: `(value: string) => void`. Runs on Enter, outside IME composition. When supplied, it prevents implicit form submission, then the input blurs. Without it, native form behavior remains available.
- Other native div events apply to the outer wrapper. Native input events belong in `inputAttributes` unless a named callback is provided. No drag or animation lifecycle callbacks are exposed.
