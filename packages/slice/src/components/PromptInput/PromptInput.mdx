# PromptInput

An AI-ready text box for adding messaging to your app. Combine prompts, file attachments, model selection, and send/stop controls in one customizable composer.

Connect your message and attachment state, then use `onSubmit` to send them to your model. Add controls to the actions bar to fit your AI experience.

```tsx
import { PromptInput, type FileItem } from '@apple-pie/slice';
import { useState } from 'react';

export function MessageComposer() {
  const [value, setValue] = useState('');
  const [attachments, setAttachments] = useState<FileItem[]>([]);
  return <PromptInput fileListProps={{variant: 'attachments', attachmentSize: 's'}} value={value} onChange={setValue}
    attachments={attachments} onAttachmentsChange={setAttachments}
    onSubmit={(message, files) => console.log(message, files)} />;
}
```

## Drag and drop

Drop files anywhere in the composer to add attachments. Drops share the picker's `acceptedTypes`, `multiple`, `onReject`, and attachment state callbacks. `disabled`, `readOnly`, `attachmentsDisabled`, and controlled attachments without a change handler block file addition. The composer highlights while files hover over it; text dragging keeps native editor behavior.

Call `preventDefault()` in `onDrop` to handle a drop yourself. The application owns uploading the attached files; the attach button remains the keyboard-accessible alternative.

## Custom actions and paste

Children can be normal controls or a render function receiving PromptActions. Clicking an empty part of the composer focuses the editor. Interactive controls retain their own focus, and selecting text does not move focus. Commands use the latest committed state, including when retained across an asynchronous clipboard read.

```tsx
<PromptInput pasteAttachmentThreshold={200}
  fileListProps={{variant: 'attachments', attachmentSize: 's'}}
  onSubmit={(message, files) => console.log(message, files)} />
```

Paste plain text directly into the editor. Content strictly longer than the limit becomes Pasted-text.txt through the shared validator; equal/shorter content inserts inline. A rejected conversion reports an error and leaves the editor unchanged. With attachment mutation disabled, content stays inline and follows maxLength. Commands preserve the editor selection/caret.

```ts
type PromptActions = {
  value: string;
  attachments: FileItem[];
  canSubmit: boolean;
  canAttach: boolean;
  disabled: boolean; // editing actions are unavailable
  focus(): void;
  submit(): void;
  stop(): void;
  openFilePicker(): void;
  addFiles(files: File[]): boolean;
  pasteText(text: string): void;
};
```

## Events

- `onAttachmentsChange: (attachments: FileItem[]) => void`: Complete next attachment array after file selection, drop, paste conversion, or removal. Pass a file-array state setter directly.
- `onBlur: (value: string, attachments: FileItem[]) => void`: Runs for a native editor blur, once per focus transition.
- `onChange: (value: string, attachments: FileItem[]) => void`: Runs for text edits and attachment changes. A string state setter can be assigned directly; the second argument supplies current attachments.
- `onFocus: (value: string, attachments: FileItem[]) => void`: Runs for a native editor focus, once per transition.
- `onKeyDown: (event: React.KeyboardEvent<HTMLTextAreaElement>) => void`: Runs before editor key handling. preventDefault cancels the corresponding internal behavior.
- `onPaste: (event: React.ClipboardEvent<HTMLTextAreaElement>) => void`: Runs before threshold conversion. preventDefault lets the application handle the paste itself.
- `onReject: (files: UploadFileRejection[]) => void`: Rejected file/reason pairs, using UploadArea’s type and multiple reasons. Visible rejection feedback is automatic.
- `onStop: () => void`: Explicit stop action. The application updates working/stopEnabled; editor focus is restored.
- `onSubmit: (value: string, attachments: FileItem[]) => void`: Ready prompt submission from the native action, Enter, or an action command. Requires trimmed text or ready attachments; uploading/error attachments block it. The application owns async work.
- `onToolTip: (tip: ToolTip | null) => void`: Shared Button/IconButton and FileList tooltips, directly composable with an app-wide Tip handler.
- `nativeEvents: React.HTMLAttributes<HTMLDivElement>`: Other native DOM events apply to the outer wrapper.

## Behavior and accessibility

Text and attachments can be controlled independently or initialized with defaults. Direct string/file-array setters work without adapters. Controlled attachments require onAttachmentsChange for mutation. Submission requires trimmed text or ready attachments, and is blocked by uploading/error attachments, disabled/readOnly, stop mode, or working with submitWorking. Async work belongs to the application.

Submission clears text by default and keeps editor focus; the application decides when to clear attachments. Enter submits, while Shift/modifier Enter and IME composition retain TextArea behavior. Stop is an explicitly named native action. Native focus/blur callbacks run for editor focus transitions. Child presentation props cannot replace owned values, refs, callbacks, or submission state.

The shared picker accepts normalized extensions or explicit MIME rules, preserves IDs while appending, and reports typed rejections. FileList handles accessible progress, errors, and removal. Artwork remains decorative; composer motion respects live reduced-motion preferences. A forwarded ref and inherited native attributes apply to the outer div. maxHeight constrains the editor through TextArea, leaving the actions bar available; numeric values use pixels and CSS strings are supported.

Use borderColorFocused in place of the removed borderColorOn. The obsolete submitEnablesStop entry has been removed; applications set stopEnabled explicitly.
