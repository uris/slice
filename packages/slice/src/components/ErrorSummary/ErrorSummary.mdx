# ErrorSummary

Bring validation messages together and help people get back to the right field.

## Usage

Place the summary above the fields, typically at the top of a large form. It collects errors across fields; each field can retain its own error message.

```tsx
import { ErrorSummary } from '@apple-pie/slice';

<ErrorSummary entries={[
  { id: 'email', title: 'Email address required', message: 'Add an email address to continue.' },
  { id: 'project', title: 'Choose a project' },
]} />
```

### Connect errors to fields

```tsx
import { useState } from 'react';
import { ErrorSummary, type ErrorMessage, TextField } from '@apple-pie/slice';

function ContactForm() {
  const [email, setEmail] = useState('');
  const [errors, setErrors] = useState<ErrorMessage[]>([]);

  return <form onSubmit={(event) => {
    event.preventDefault();
    setErrors(email.trim() ? [] : [{
      id: 'email-required',
      title: 'Email address required',
      message: 'Add an email address to continue.',
      fieldName: 'email',
    }]);
  }}>
    <ErrorSummary entries={errors} />
    <TextField name="email" inputName="Email address" value={email}
      onChange={(next) => setEmail(next ?? '')} />
    <button type="submit">Continue</button>
  </form>;
}
```

### Show errors as you type

This demo treats every entered value as invalid. Your app supplies the validation rules.

```tsx
function LiveValidation() {
  const [value, setValue] = useState('');
  const errors: ErrorMessage[] = value.length > 0 ? [{
    id: 'example-value',
    title: 'Value not accepted',
    message: 'Choose a different value.',
    fieldName: 'example-value',
  }] : [];

  return <form onSubmit={(event) => event.preventDefault()}>
    <ErrorSummary entries={errors} />
    <TextField name="example-value" inputName="Example value"
      placeholder="Enter a value" value={value}
      onChange={(next) => setValue(next ?? '')} error={errors.length > 0} />
  </form>;
}
```

## Behavior

Errors are unnumbered groups with optional bullet messages. Blank messages are omitted; repeated messages are supported. The panel animates its actual height without a clipping ceiling. Field navigation searches its surrounding form first, or the document when outside a form, matching the native `name` of a visible enabled input, select, or textarea. It focuses that control and scrolls its parent into view. Missing targets do nothing. An empty array hides the panel while preserving the announcement region.

## Accessibility

Updates are announced politely by default. Keep the summary mounted before validation updates. Use `summaryName` for its accessible name and `announcement` for urgency or to disable announcements. Showing errors does not move focus automatically. Field titles are native buttons when `fieldName` is supplied. A forwarded `ref` points to the outer div for application-managed focus. Reduced motion disables panel animation and smooth navigation scrolling, including live preference changes.

## Props

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `announcement` | `'polite' ∣ 'assertive' ∣ 'off'` | `polite` | Controls announcements of updated errors. `polite` waits for a pause, `assertive` requests immediate attention, and `off` disables announcements. |
| `backgroundColor` | `ColorValue` | `feedback-warning at 10% opacity` | Panel background. |
| `borderColor` | `ColorValue` | `feedback-warning` | Panel border color, independent of `textColor`. |
| `borderRadius` | `number ∣ string` | `corner-xs (4px)` | Panel corner radius in pixels or CSS units. |
| `borderWidth` | `number ∣ string` | `1` | Border width in pixels or CSS units. Zero removes the border. |
| `entries` | `ErrorMessage[]` | `undefined` | Current validation errors. An empty or omitted array hides the visible panel while retaining its announcement region. |
| `gap` | `number ∣ string` | `spacing-xs (4px)` | Space between error groups, in pixels or CSS units. |
| `padding` | `number ∣ string` | `spacing-m (16px)` | Panel padding. Numeric values become pixels; CSS shorthands and zero are applied exactly. |
| `summaryName` | `string` | `Errors to review` | Accessible name for the summary. Blank names use the fallback. |
| `textColor` | `ColorValue` | `feedback-warning` | Color of titles, messages, and field actions. |
| `textSize` | `'xs' ∣ 's' ∣ 'm' ∣ 'l' ∣ 'xl'` | `m` | Slice body text size for titles and messages. |
| `divAttributes` | `React.HTMLAttributes<HTMLDivElement>` | `undefined` | Native attributes and events apply to the persistent outer wrapper. `className` is appended and `style` is merged; component CSS variables take priority. Content, roles, and raw ARIA attributes are managed internally. |

### ErrorMessage

```ts
type ErrorMessage = {
  id?: string;
  title: string;
  message?: string | string[];
  fieldName?: string;
};
```

Use `id` for stable identity during changes or reordering. Identity otherwise falls back to `fieldName` or `title`. `fieldName` matches the control’s native `name`, rather than its accessible name.

## Motion

Appearance and removal use an internal `AnimatePresence` and Motion element: opacity fades from 0 to 1 while height expands from 0 to auto; exit reverses both. You do not need to wrap the summary yourself.

```tsx
<ErrorSummary
  entries={errors}
  transition={{ duration: 0.35 }}
  motionValues={{
    initial: { y: -8 },
    animate: { y: 0 },
    exit: { y: -8 },
  }}
/>
```

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `motionValues` | `Variants` | Fade and height expansion | Overrides the `initial`, `animate`, and `exit` states. Partial object overrides retain default height and opacity values. |
| `transition` | `Transition` | Water | Settings are merged with Slice’s Water transition. |

Defaults are `initial: { height: 0, opacity: 0 }`, `animate: { height: 'auto', opacity: 1 }`, and `exit: { height: 0, opacity: 0 }`. Reduced motion bypasses custom variants, delays, and repeats, including live preference changes.

## Events

Native div events apply to the persistent outer wrapper; field actions bubble normally. No component-specific callbacks or Motion gesture callbacks are exposed.

## Ref

The forwarded ref points to the outer `HTMLDivElement`. With visible entries it can be focused through `ref.current?.focus()`.
