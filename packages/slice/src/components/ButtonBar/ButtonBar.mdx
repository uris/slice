# ButtonBar

Group related actions in a horizontal or vertical stack, with shared styling and optional separators.

## Usage

```tsx
import { Button, ButtonBar } from '@apple-pie/slice';

export function DocumentActions() {
  return (
    <ButtonBar aria-label="Document actions">
      <Button label="Edit" iconLeft="editor.edit" />
      <Button label="Options" iconRight="arrows.chevron-down" />
      <Button iconLeft="basic.more-horiz-fill" aria-label="More actions" />
    </ButtonBar>
  );
}
```

Or supply Button props:

```tsx
<ButtonBar
  aria-label="Document actions"
  buttons={[{ label: 'Edit' }, { label: 'Duplicate' }, { label: 'Archive' }]}
/>
```

## Compose a text field

```tsx
<ButtonBar aria-label="Quantity" onChange={setQuantity}>
  <Button iconLeft="basic.plus" aria-label="Increase" onClick={increase} />
  <TextField inputName="Quantity" width={120} value={quantity} textAlign="center" />
  <Button iconLeft="basic.minus" aria-label="Decrease" onClick={decrease} />
</ButtonBar>
```

Import `TextField` from `@apple-pie/slice`. The application owns `quantity`, `setQuantity`, `increase`, and `decrease`.
The bar fits its children by default. A field keeps its explicit width; without one it uses content sizing.
Its variant is always `simple`, its height follows `buttonSize`, and its border/radius are removed to share the frame.
TextFields retain their own padding, including their standard defaults. The bar's padding props apply only to buttons; `inset` adds separate space at the outer edges.
Other field callbacks stay on the field; Button callbacks remain button-only.

## Behavior

Defined parent styles override child styles. Omitted values preserve child settings before applying bar defaults. Borders and corners belong to the wrapper; child buttons are square and borderless. When both APIs are used, button definitions render before composed children. The bar does not manage selection.

## Accessibility

The wrapper uses role="group". Name it with aria-label or aria-labelledby, and give icon-only buttons their own aria-label. Buttons retain native Tab, Enter, and Space behavior. Separators are decorative. Focusing any child changes the wrapper border color. Buttons additionally retain their inset keyboard focus ring.

## Events

Child callbacks run before parent callbacks. Parent click/change callbacks receive the original event/value followed by item metadata. Parent handlers receive button events rather than wrapper events. onClick can receive undefined for programmatic or deferred Button activation; onToolTip receives a tooltip or null to dismiss it.

- `onChange`: `(value: string, item: ButtonBarItemInfo) => void`, forwarded from composed TextField children after their own callback. Item details include the zero-based mixed-item index, label (label/inputName/name), and optional ID (inputId/id). Does not run for button clicks or programmatic value updates.
- `onClick`: `(event: Parameters<NonNullable<ButtonProps["onClick"]>>[0], item: ButtonBarItemClickInfo) => void`. Item details include zero-based `index`, optional `id`, and `label` from text content or an accessible label/tooltip. The index counts every processed item, including TextFields; definitions render before composed children. Use explicit button IDs for stable identity when reordering.
- `onToolTip`: `ButtonProps["onToolTip"]`.
- Other Button event callbacks (for example `onFocus`, `onBlur`, and pointer events) are forwarded using their Button signatures.

## Migration

The previous icon-record API has been replaced. Use `ButtonProps` (`iconLeft` and `aria-label` instead of `icon` and `tip`), and handle actions in each Button or the bar callback. `BarButton`, `toggle`, `selectedIndex`, `defaultSelectedIndex`, `selectionRadius`, and `buttonGap` are removed. Use `inset` for outer content spacing and `divider` for separators. `onClick` now receives the Button event rather than an item record; selection belongs to the application.
