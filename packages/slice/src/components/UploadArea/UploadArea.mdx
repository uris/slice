# UploadArea

Select or drop files with shared validation and controlled attachment state. The application owns uploading.

```tsx
import { UploadArea, type FileItem } from '@apple-pie/slice';
import { useState } from 'react';

export function Attachments() {
  const [files, setFiles] = useState<FileItem[]>([]);
  return <UploadArea files={files} onFilesChange={setFiles} acceptedTypes={['pdf', 'png']} />;
}
```

Numbers for dimensions and padding use pixels. Colors accept Slice tokens or CSS colors. Use borderWidth/borderRadius; the border/radius aliases have been removed. A forwarded ref targets the wrapper HTMLDivElement.

## Selection and events

- `onFilesChange?: (files: FileItem[]) => void`: complete next array after selection or removal; pass a state setter directly.
- `onUpload?: (files: File[]) => void`: only newly accepted files, after onFilesChange. Start upload work here; do not append the same files again.
- `onReject?: (files: UploadFileRejection[]) => void`: each entry contains a File and reason `type` or `multiple`. Visible rejection feedback is automatic.
- `onToolTip?: (tip: ToolTip | null) => void`: forwards FileList remove-action tooltips.

Extension rules compare File.name case-insensitively, independently of MIME type. Explicit MIME types and image/*, audio/*, video/* rules use File.type. Presets imageTypes, videoTypes, documentTypes, audioTypes, textTypes, and allTypes contain extensions normalized internally. All-invalid configuration rejects all files rather than allowing every type. Empty selections emit no callbacks; fully rejected selections preserve existing files.

Multiple selection appends to existing objects. Single mode replaces with the first accepted file. New attachments receive stable IDs. The component does not upload files or store the controlled array.

Native wrapper events are forwarded. Drag handlers run before internal logic; preventDefault in onDragEnter or onDrop cancels that event's internal handling. onClickCapture can cancel picker activation. Drag cleanup still runs after cancellation.

## Accessibility

A native button supports Enter/Space and keyboard-only focus outlines. Existing files do not disable picker access. Busy/disabled states affect the trigger and removal actions without disabling the list's ancestor. Busy activity is a polite status announcement; rejected files use an alert. Artwork and spinners are decorative. FileList supplies accessible progress/errors and named removal controls. Removing the final attachment returns focus to the picker. The spinner respects reduced motion; drag highlighting resets on availability changes, drag end, Escape, and window blur.

## Attachment cards

Pass FileList presentation options directly. Attachment cards wrap in a row by default; compact file rows use a column.

```tsx
<UploadArea files={files} onFilesChange={setFiles}
  fileListProps={{variant: 'attachments', attachmentSize: 's'}} />
```
