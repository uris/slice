        # UploadsWorker Class
        Queue-based file uploader used by the Slice uploads worker runtime. It handles:
        - queueing browser `File` objects
        - client-side file size and type validation
        - configurable upload concurrency
        - per-file upload URL overrides
        - progress/status updates through a worker bridge
        - worker-runtime message handling through `UploadsWorkerRuntime`

        ## Public vs internal usage
        For application code, prefer the published worker entry and uploads store helpers:

        <RenderSource>
        ```
        import uploadsWorkerUrl from '@apple-pie/slice/workers/uploads/uploads?url';
        import { createUploadsWorker } from '@apple-pie/slice/stores/uploads';
        
        const worker = createUploadsWorker(uploadsWorkerUrl);
        ```
        </RenderSource>

        The class documented on this page lives in the source worker module and is mainly useful inside the repo, in tests, or in custom worker setups.

        ## Queue behavior
        `UploadsWorker` enforces a few important behaviors:
        - If the queue is already at <code>maxQueueSize</code>, additional files are ignored rather than queued.
        - Files larger than <code>maxFileSize</code> fail immediately with <code>UploadError.SizeExceedsLimit</code>.
        - If <code>accepted</code> is configured, the worker matches either the file extension or MIME type.
        - Each upload uses its own <code>uploadURL</code> when provided; otherwise it falls back to the worker-level <code>uploadURL</code>.
        - Uploads are sent as <code>POST</code> requests with a <code>FormData</code> payload containing one field named <code>file</code>.

        ## Direct class usage
        This is useful in tests or local tools where you want status snapshots without spinning up a full `Worker`.

        <RenderSource language={'typescript'}>
        ```
        import {
            UploadsWorker,
            type Upload,
            type UploadWorkerBridge,
        } from './uploads-worker';
        
        const snapshots: Upload[][] = [];
        
        const bridge: UploadWorkerBridge = {
            updateStatus(uploads) {
                snapshots.push(uploads);
            },
        };
        
        const uploads = new UploadsWorker(
            {
                uploadURL: '/api/uploads',
                maxConcurrentUploads: 2,
                accepted: ['png', 'image/png'],
            },
            bridge,
        );
        
        uploads.addFiles([
            fileA,
            { file: fileB, uploadURL: presignedUrl },
        ]);
        ```
</RenderSource>

        ## Registering the worker runtime
        The published uploads worker entry simply registers this runtime against the current worker global:

        <RenderSource>
{`
import { registerUploadsWorker } from './uploads-worker';

registerUploadsWorker();
`}
</RenderSource>

        If you need to mount the runtime onto a custom message target in tests, instantiate it directly:

        <RenderSource>
{`
const runtime = new UploadsWorkerRuntime(customTarget);
`}
</RenderSource>

        ## Operational note
        `clearUploads()` clears the worker's tracked state immediately, but it does not currently abort in-flight network requests. Use it as a state reset, not as a guaranteed transport-level cancel operation.
