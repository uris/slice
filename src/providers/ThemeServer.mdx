        # ThemeServer
        Server-safe helpers for SSR-enabled environments such as Next.js. These helpers resolve a startup theme before hydration and provide the root HTML attributes needed for first-paint theming.
        They are designed to pair with the `slice-theme` and `slice-system-theme` cookies written by `ThemeProvider` on the client.

        ## Import Paths
        Use the server helpers from:

        `@apple-pie/slice/providers/themeServer`

        Use the client runtime provider from:

        `@apple-pie/slice/providers/ThemeProvider`

        ## Recommended SSR flow
        - Read the `slice-theme` and `slice-system-theme` cookies on the server.
        - Pass those values into `resolveInitialTheme()`.
        - Spread `getThemeHtmlAttributes(initialTheme)` onto the root `html` element.
        - Pass the same `initialTheme` and `initialSystem` into `ThemeProvider` on the client.
        - Let `ThemeProvider` refresh the cookie after hydration so future requests keep the same resolved theme.

        ## Cookie behavior
        - Cookie name: `slice-theme`
        - Cookie value: the resolved Slice theme name such as `lightMode` or `darkMode`
        - Cookie name: `slice-system-theme`
        - Cookie value: `true` when the active theme is still system-derived, otherwise `false`
        - Cookie attributes: `path=/`, `max-age=31536000`, `SameSite=Lax`
        - Intended use: lets SSR code read the last resolved client theme and whether it came from system mode before hydration


        ## Next.js Example
        </Unstyled>

        <RenderSource language={"tsx"}>
        ```
        import { cookies } from 'next/headers';
        import {
            getThemeHtmlAttributes,
            resolveInitialTheme,
        } from '@apple-pie/slice/providers/themeServer';
        import { ThemeProvider } from '@apple-pie/slice/providers/ThemeProvider';
        
        export default async function RootLayout({
            children,
        }: {
            children: React.ReactNode;
        }) {
            const cookieStore = await cookies();
            const systemThemeCookie = cookieStore.get('slice-system-theme')?.value;
        
            const { initialTheme, initialSystem } = resolveInitialTheme({
                activeTheme: cookieStore.get('slice-theme')?.value,
                systemTheme:
                    systemThemeCookie === undefined
                        ? undefined
                        : systemThemeCookie === 'true',
            });
        
            return (
                <html lang="en" {...getThemeHtmlAttributes(initialTheme)}>
                    <body>
                        <ThemeProvider
                            initialTheme={initialTheme}
                            initialSystem={initialSystem}
                            global
                        >
                            {children}
                        </ThemeProvider>
                    </body>
                </html>
            );
        }
        ```
        </RenderSource>

        <Unstyled>
        ## Notes
        - `ThemeProvider` remains the client-side runtime piece.
        - The server helpers exist to make the first HTML response theme-aware before React hydration begins.
        - `ThemeProvider` passes the same `initialTheme` and `initialSystem` values into Slice's internal theme context so `useTheme()` and `useObserveTheme()` match the server render during hydration.
        - The expected cookie names are `slice-theme` and `slice-system-theme`.
        - When `systemTheme` is missing during SSR resolution, `resolveInitialTheme()` defaults `initialSystem` to `true`.
        - When no explicit startup theme is available, `resolveInitialTheme()` and `getThemeHtmlAttributes()` fall back to `darkMode`.
        - If you only set the theme in a client effect, the first paint may occur before the theme attribute is applied and you get a UI flicker.
